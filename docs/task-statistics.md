# 场景完成通知与统计

在「场景路由 → 编辑场景」中开启「完成通知与统计 / 发送任务统计卡片」。新场景与迁移后的现有场景默认关闭。

统计卡片仅在以下条件全部满足时发送：当前场景已开启开关、消息来自用户、本次消息的结构化 mentions 明确包含当前 Bot、完整回复的所有分页已成功投递、能够取得发起用户在当前应用下的 open_id。

话题内自动接话、未明确 @ 当前 Bot 的私聊、其他机器人发来的消息、无场景的默认回复不发送统计卡片。统计卡片回复原消息，沿用该场景原有的普通群 / 话题投递方式，@ 的是消息发起人。

## 口径

- 处理时间：从原生 Turn 开始执行到完整结果送达，不包含队列等待；不包含随后统计卡片自身的发送耗时。
- Token：通过 Core 已有 AppServerHost 订阅原生 `thread/tokenUsage/updated`，只采集当前 Thread、当前 Turn。使用原生累计计数的差值，包含本轮多次模型调用。已有计数在原生 Turn 入队完成后建立基线；首次接入已有 Thread 时，通过首条事件的 `total - last` 建立基线。
- 无可靠计数、计数缺失或发生重置时显示「暂无数据」，不估算，不用整个 Thread 的历史用量代替。本次实现沿用 Codex 原生 inputTokens/outputTokens/totalTokens 口径；inputTokens 包含模型实际使用的上下文，不等于输入字符数。
- 输入字符：本次标准化后的用户消息文字，排除系统 Prompt、附件内容及运行信息。
- 输出字符：最终助手回复正文，排除思考、工具日志、统计卡片及运行信息。
- 字符按 Unicode code point 计数，避免把普通 emoji 的 UTF-16 代理对算作两个字符。

执行失败或正文未送达，不发送「处理完成」统计卡片。统计卡片发送失败记录警告，不改变正文已成功送达的任务结果。去重 ID 是稳定的 40 字符哈希，重试保持一致，并满足飞书 50 字符上限。

## 分层

场景配置、耗时、字符数、发送条件和卡片编排均由 CodyBotHub 实现。Core 已提供原生用量事件订阅，本次不修改或升级 Core。
