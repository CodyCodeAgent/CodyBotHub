# AI 定时任务工作台

定时任务独立选择工作区、引擎、模型、Prompt 和能力，不要求绑定 Bot 或场景。后台代码负责持久调度、互斥、审计和恢复；AI 使用工作区技能与知识完成任务。需要报告投递或工具包审批时，才配置飞书 Bot 和接收群。

## 页面与使用

侧边栏「编排 → 定时任务」包含任务列表、执行记录、任务模板。工作区列表也提供关联入口。

1. 从模板或自定义任务开始，选择工作区、引擎和模型，填写 Prompt。
2. 选择技能包。执行受管维护或业务工具包时，选择「维护与工具执行」，并明确选择工具包；工具包必须属于该工作区。
3. 配置间隔、每日、每周或五段 Cron，填写 IANA 时区。服务器预览未来三次执行时间。
4. 结果默认只保存平台。需要发送报告或审批卡片时，选择关联该工作区的 Bot 和接收群 Chat ID。
5. 默认保存为暂停状态。先手动执行，查看结果、步骤、实际模型和 Thread ID，再启用计划。

任务修改仅影响后续执行；运行中的任务使用已保存快照。暂停计划不会强行中断当前执行。归档保留历史，未结束的执行必须先处理。有关联任务记录的工作区受数据库关联保护，不能直接删除。

任务列表和活动执行详情每五秒刷新；离页或隐藏标签后停止。编辑页面不自动刷新表单。任务和记录均在服务器分页，默认每页二十条。

## 模型与上下文

模型和推理强度分别按「任务配置 → 平台配置 → 引擎账户默认」解析，选项读取当前引擎目录。运行记录保存实际值和原生 Thread ID。

默认每次创建独立 Thread，附带上次成功结果摘要。也可复用该任务的专属 Thread；同一任务不会并行运行，线程不与群会话混用。审批结果续写本次任务 Thread。完整对话以原生引擎历史为准，Hub 只保存任务快照、报告和工具结果。

Prompt 支持以下文本变量，不执行表达式：

- `{{current_time}}`：当前 UTC ISO 时间。
- `{{run_id}}`：本次执行 ID。
- `{{last_success_at}}`：上次成功结束时间。
- `{{last_result_summary}}`：有长度限制的上次成功报告摘要。

原生模型沙箱为只读并允许网络查询；维护写入通过受管动态工具执行。Prompt 不是操作系统或网络权限边界。已有 MCP/CLI 的远端权限仍由各自的认证和服务端策略控制。

## 调度与重启

SQLite 保存任务、执行、步骤、审批和调度器租约。任务 ID 和计划时间构成唯一触发键。进程内最多两个任务同时执行，同一路径、路径别名和嵌套工作区的定时执行不同时派发。

上次未结束时默认跳过并记录，也可只合并一个待执行。错过超过三十秒触发窗口的计划记录为跳过，再计算下一次时间，避免重启后批量执行历史操作。恢复启用也从当前时间重新计算。

尚未启动的排队任务可以恢复。已运行且中断的任务标为「已中断，需核实」，不会自动重跑整轮；外部动作可能已经完成。取消运行中的任务表示请求中断，不表示外部动作回滚。当前执行器中的命令可能需要等自身超时或结束后才能完成中断。

`SIGUSR2` 同时停止飞书、MCP 和定时任务的新派发，保持已接收任务持久化。部署状态统计定时执行；部署脚本等待所有活动任务结束再重启。`SIGUSR1` 取消排空。

## 工作区资源同步模板

通过 `codybothub_tasks.inspect_workspace`、`sync_workspace`、`verify_resources` 提供受管能力，AI 负责维护目标、选择调用和解释异常。

- 主仓库跟踪明确分支，只接受快进；不自动切换主分支，不清理未跟踪配置，不覆盖已跟踪本地修改。
- 可在任务中填写 `preserveLocalFiles` 本机保留清单，每行一个主仓库已跟踪普通文件的精确相对路径。清单内文件（每个最多 8 MiB）在维护窗口中先校验、备份，再临时还原仓库版本完成快进，随后恢复本机完整内容与权限。远端修改这些文件时只记录版本与哈希并提示人工核对，不自动合并；清单外本地修改、暂存修改、符号链接、路径越界、远端删除或改名仍会阻止更新。
- `sync_workspace` 可传 `preserveLocalFiles` 和 `submodulePaths`，只能选任务配置中的一部分；不传则沿用全部配置。Prompt 可以决定使用哪些已授权项，不能扩展范围。没有选择子模块时，仅更新主仓库，不会更新知识库/服务子模块。
- 子模块需在工作区先完成初始化。可跟随主仓库固定提交，或指定远端分支。嵌套子模块按其父仓库指定提交递归更新。必选模块失败阻止应用；可选模块失败保留旧版本并记录警告。
- 分支快进检查遇到浅克隆时，会有限补全历史（两轮，分别追加 200、1000 层）后再判断，不因缺少历史直接覆盖。子模块还可明确选择「合并远端，保留本地提交」：先在 Git 对象库预检，仅无冲突时生成包含双方历史的本地合并提交；不改写或推送远端。有冲突只报告文件名，工作目录与原提交保持不变。可选子模块冲突时跳过该模块，其余继续；必选项冲突则停止整轮。
- 拉取和准备不暂停消息处理。应用前申请工作区维护窗口，暂停新的使用者进入，等待已运行的消息、Copilot、MCP 和工具操作结束，最多等待十五分钟。飞书连接保持在线，消息仍可接收和排队。
- 扫描相对技能根目录，新增技能安装到 `.codex/skills`；相同内容不重复安装。本地修改、同名来源冲突保留并报告，远端删除不自动卸载。
- 单个技能名称不适合作为安装目录时，记录具体来源和名称并跳过，不撤销其他代码更新；路径越界、目录外符号链接及整体资源验证失败仍会触发恢复。
- 更新目录时保留 `.venv`、`node_modules`、本地 `.env`、缓存和本地配置。不复制远端虚拟环境，不自动安装依赖，也不部署或重启平台。
- Git 管理的知识库随所选子模块更新，资源索引验证读取引擎技能目录和工作区知识根目录。
- 可额外同步已配置的独立技能源。任务开启自动安装时会完成其技能安装。独立来源可能部分完成；失败记录会提示核实，不承诺所有来源之间的整轮原子事务。

每次同步在 `.data/workspace-sync/<执行 ID>/journal.json` 保存精确版本清单和阶段，Git 中保留 `refs/codybothub-backups/<执行 ID>`，技能目录保留恢复副本。验证失败尝试恢复本轮代码和技能；若恢复失败或进程在应用阶段崩溃，工作区进入持久维护暂停。管理员检查日志、代码、技能及环境后，可在该工作区的定时任务页面解除维护暂停。不要在未核实状态时解除。

平台管理的执行经过工作区协调；外部 SSH 或其他进程直接修改文件不受此锁控制，因此应用前仍会复查版本和本地修改。

## 工具包与审批

定时任务只允许调用其明确选择且属于同一工作区的工具包。调用前创建持久请求，参数和工具版本留存。需要审批的包发送飞书确认卡，校验当前 Bot 应用命名空间下的审批身份，沿用工具包审批人、Bot 操作人和管理员回退规则。

审批最长等待六小时。等待期间释放 AI worker；确认后执行，拒绝或过期后把真实结果送回本次任务 Thread，同一工具包本轮不重复申请。审批后若工具或工具包发生变化，拒绝执行旧请求。相同参数的请求使用稳定哈希去重，每轮最多十个工具包请求。

已进入外部操作的失败或进程中断不能保证外部系统回滚。系统不声称通用 exactly-once；需要业务接口幂等或人工核实。

## 报告、投递与排查

执行成功/警告/失败和报告投递状态独立记录。投递失败只重发报告，保留已发送分段记录，不重新调用模型或业务工具。卡片采用原有 Markdown 拆分和表格兼容渲染。

执行详情先展示报告和错误，再展示工具包请求、阶段结果和配置快照。只展示最终报告与可审计工具事件，不展示思考摘要。排查信息包括执行 ID、Task ID、Thread ID、实际模型和错误，可复制。

第一版不自动删除执行记录或备份；需要按存储情况人工制定清理策略。不要将 `.data` 中的备份、记录或认证文件提交到 Git。

## 接口与实现位置

- `GET/POST /api/scheduled-tasks`：分页查询、创建。
- `GET/PUT/DELETE /api/scheduled-tasks/:id`：查看、修改、归档。
- `POST /api/scheduled-tasks/:id/run`：创建手动执行。
- `PUT /api/scheduled-tasks/:id/enabled`：启停后续计划。
- `GET /api/scheduled-runs`、`GET /api/scheduled-runs/:id`：分页记录、详情。
- `POST /api/scheduled-runs/:id/cancel`：取消或请求中断。
- `POST /api/scheduled-runs/:id/delivery`：仅重试失败投递。
- `GET /api/scheduled-templates`、`POST /api/scheduled-preview`：模板、计划预览。
- `GET /api/scheduled-workspace?workspaceId=...`：只读识别仓库。
- `GET/POST /api/scheduled-maintenance`：查看维护暂停、管理员核实后解除。
- `GET /api/scheduled-health`：调度器和任务统计。

所有接口要求平台登录，写接口沿用跨源检查，创建、修改、启停、触发、归档、取消和重投递写入操作记录。

产品逻辑在 Hub 的 `scheduled.ts`、`scheduled-store.ts`、`schedule.ts`、`workspace-access.ts` 和 `workspace-sync.ts`。复用 Core 的连接、模型目录和原生 Thread，不放开原有 MCP 只读任务入口。
